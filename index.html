1Lunch break in the My Timesheet calendar

The gap between two entries around midday is shown as a lunch break across all project columns of the day. It is not counted in any total.

Sample data. The 15:45–16:00 gap stays a plain gap: it is outside the lunch window.

How it behaves

  • A gap counts as lunch if it touches 11:00–12:30, lasts at least 15 minutes, and is the longest such gap of the day. There's no upper limit.
  • It is measured across all projects of the day, so a gap between project A and project B counts too.
  • Only confirmed entries count, so the calendar shows exactly the break that the working-time record prints.
  • The band is display only: it can't be dragged, edited or confirmed. It has no status of its own.
  • Entries on a break project (§5) use the same striped style and are also left out of every total.

How it behaves

  • Arbeitszeitnachweis: one employee per month. Start = first entry, end = last entry, the break from §1, hours = sum of entries, +/- against the employee's daily target (§4), weekly sums Monday to Sunday. The footer reads “Stunden = Summe der Einträge”.
  • Gesamtbericht: month or year. For each employee: productive hours, hours per project (largest first), vacation and sick days counted up to today.
  • Filters as in the existing hours report: period, employees, and projects (Gesamtbericht only).
  • Employees see only their own data and have no employee filter. Naming a colleague is refused, not silently swapped.
  • Colleagues' vacation and sick figures appear only with reports.view_hr. Without it, those cells are empty.
  • Public holidays show FT with 0,00 difference. Work logged on a holiday counts as plus hours.

How it behaves

  • The default is 8,00 for everyone, including existing staff.
  • A change applies from its date onward. Earlier days and signed lists keep the old value.
  • Outside the employment period the target is 0, so a mid-month joiner or leaver gets no minus hours.
  • Every change is logged: who, when, old and new value. An end date before the start date is refused.
  • Absence days count as the target minus any hours worked that day. Unpaid leave counts 0.

5Break project (Projects → edit)

A project such as “Pause” can be marked as a break project. The switch is visible only to holders of the new project.manage_break_flag permission (IT Administrator and Manager). Project Leads don't see it.

Project panel · new switch

Pausenprojekt

Sample numbers.

How it behaves

  • Turning it on or off asks for confirmation and shows how many existing entries it affects, because it changes past reports.
  • It's based on a fixed mark, not the project's name. Renaming the project changes nothing.
  • At release we set it once on the existing “Pause” project.
  • It's a separate permission from editing project details, so a Project Lead can't hide their project's hours.

Takes 0,5 days from the balance and counts half the daily target (8,00 → 4,00) as working time, not as productive hours. Worked hours that day still count: 4,00 work + 4,00 vacation = 8,00.

Vacation only. Sick leave stays in whole days. Not possible on weekends or public holidays.

Also fixed: in Firefox, the start and end date/time fields in Task Management overlap their calendar icons. They will show in full in Chrome, Edge and Firefox. Carried-over vacation no longer expires on 31 March, and the days that expired in March 2026 are restored.
